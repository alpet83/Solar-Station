# Конфигурация

## Обзор

Это справочник всех путей, констант и порогов, используемых скриптами Solar-Station; для процедуры установки и деплоя см. [Установку и деплой](02-installation.md).

## Файлы состояния (/tmp)

| Файл | Кто пишет | Кто читает | Содержимое кратко |
|---|---|---|---|
| `/tmp/jkbms_last.json` | `sbin/jkbms_ctrl.py` (перезаписывает, `'w'`) | `sbin/batmon.php` | Последний снятый снимок состояния BMS (напряжения ячеек, ток/напряжение батареи, SoC, `ts`, `device_id`) |
| `/tmp/jkbms_stats.json` | `sbin/jkbms_ctrl.py` (дозапись, `'a'`) | `sbin/backup_stats.sh` (архивирует) | Накопительный лог показаний BMS, по строке JSON за опрос |
| `/tmp/inverter_last.json` | `sbin/pv1800_ctrl.py` (перезаписывает, `'w'`) | `sbin/batmon.php` (не читается напрямую в показанном коде, но используется как «последний снимок»), `sbin/backup_stats.sh` (архивирует) | Последний снятый снимок показаний инвертора (напряжения/токи/мощности фаз, температуры, реле и т.д.) |
| `/tmp/inverter_accum.json` | `sbin/pv1800_ctrl.py` (перезаписывает, `'w'`) | `sbin/batmon.php` | Накопительные счётчики энергии (`load_power`, `buy_power`, `sell_power`, `charger_power`, `discharger_power`, `self_use`, `PV_sell_power`, `grid_charger`) |
| `/tmp/inverter_cfg.json` | `sbin/pv1800_ctrl.py` (перезаписывает, `'w'`) | `sbin/batmon.php` (поле `config->ongrid_switch`) | Текущая конфигурация/режим инвертора |
| `/tmp/inverter_raw.json` | `sbin/pv1800_ctrl.py` (перезаписывает, `'w'`) | — | Сырые значения регистров Modbus, для отладки |
| `/tmp/inverter_stats.json` | `sbin/pv1800_ctrl.py` (дозапись, `'a'`, только при заметном изменении токов) | — | Накопительный лог показаний инвертора |
| `/tmp/epever_dump.json` | `/usr/local/sbin/epever_dump.sh` (**не входит в этот репозиторий**, отдельный скрипт хоста) | `sbin/batmon.php` (поле `battery_current`) | Показания отдельного MPPT-контроллера Epever, суммируются с зарядным током PV1800 при расчёте гистерезиса on/off-grid; если файла нет или в нём нет `battery_current`, `batmon.php` логирует предупреждение и считает эту составляющую тока нулевой |
| `/tmp/on_grid.cntr` | `sbin/batmon.php` (перезапись) | `sbin/batmon.php` (сам же читает при следующем запуске) | Счётчик гистерезиса переключения on/off-grid (от -5 до +5), переживает между запусками `batmon.php` — см. раздел [Пороги batmon.php](#пороги-batmonphp) |

## Устройства и шина

| Контроллер | Устройство | Скорость | Slave/адрес |
|---|---|---|---|
| `sbin/jkbms_ctrl.py` (JKBMS, RS485) | `/dev/ttyBMS0` (константа `port`, стабильный udev-алиас) | 115200 (константа `baud`) | `bms_id` передаётся через `--bms_id` (0 = все на шине); сигнатура протокола — `signature = "4e57"` |
| `sbin/pv1800_ctrl.py` (инвертор MUST PV1800, Modbus RTU) | `/dev/ttyINV0` (константа `DEVICE`, стабильный udev-алиас) | 19200 (константа `BAUDRATE`) | `SLAVE_ID = 0x04` |

## Стабильные имена устройств (udev)

На хосте кроме СЭС работает и другая периферия (GPS/GNSS-приёмник для точного времени, Epever MPPT-контроллер, UPS и т.д.), поэтому «сырые» кернел-имена `/dev/ttyUSB*`/`/dev/ttyACM*` не гарантированно стабильны между перезагрузками — какое имя достанется конкретному адаптеру, зависит от порядка перечисления USB при старте. На практике это уже приводило к падению обоих контроллеров сразу: после добавления GPS-приёмника без udev-правила `/dev/ttyACM0` при одной из загрузок занял GPS вместо инвертора, а `jkbms_ctrl.py` тем временем был задеплоен со ссылкой на неверный порт BMS.

Правило `etc/udev-rules/91-solar-station.rules` в этом репозитории закрепляет три алиаса по `idVendor`/`idProduct` (и `serial`, где vendor:product не уникален на шине):

| Алиас | Устройство | Ключ |
|---|---|---|
| `/dev/ttyBMS0` | JKBMS (CH340) | `idVendor=1a86, idProduct=7523` |
| `/dev/ttyINV0` | Инвертор PV1800 (USB Single Serial) | `idVendor=1a86, idProduct=55d3, serial=545C052358` |
| `/dev/ttyGPS0` | GPS/GNSS-приёмник (u-blox 7) | `idVendor=1546, idProduct=01a7` |

Установка: скопировать файл в `/etc/udev/rules.d/91-solar-station.rules` и перечитать правила — `udevadm control --reload-rules && udevadm trigger`. `jkbms_ctrl.py`/`pv1800_ctrl.py` в этом репозитории уже используют `/dev/ttyBMS0`/`/dev/ttyINV0`, а не сырые кернел-имена — при разворачивании на новом хосте нужно один раз определить реальные `idVendor`/`idProduct`/`serial` через `udevadm info -q property -n /dev/ttyUSB0` (и аналогично для остальных портов) и поправить правило под конкретные адаптеры.

## Константы в скриптах

Все перечисленные значения — константы прямо в исходном коде; менять их приходится редактированием файла скрипта (отдельного конфиг-файла для этих параметров в проекте нет — это фактическое положение дел, а не рекомендация: hardcoded-константы не самый удобный способ конфигурации, но так сделано сейчас).

### sbin/jkbms_ctrl.py

| Константа | Значение по умолчанию | Что регулирует |
|---|---|---|
| `signature` | `"4e57"` | Сигнатура протокола JK RS485/232, используется при разборе кадров |
| `port` | `/dev/ttyBMS0` (стабильный udev-алиас, см. выше) | Serial-порт для связи с BMS |
| `baud` | `115200` | Скорость порта |
| `read_all` | `b'\x4E\x57\x00\x13\x00\x00\x00\x00\x06\x03\x00\x00\x00\x00\x00\x00\x68\x00\x00\x01\x29'` | Готовый запрос "прочитать всё" (all-data) для BMS с адресом 0 |

CLI-аргументы (argparse, см. `sbin/jkbms_ctrl.py`):

| Аргумент | Тип | По умолчанию | Назначение (из help) |
|---|---|---|---|
| `--cmd` | int | `0` | `1,2,3,5,6 - activate, write, read, update, read_all` — код команды протокола |
| `--id` | int | `0` | `00, 0x79-0xba - parameter selector for r/w/u` — селектор параметра для чтения/записи/обновления |
| `--value` | str | `''` | `HEX bytes string for rewrite parameter` — HEX-строка байт значения при записи |
| `--bms_id` | int | `0` | `BMS ID on bus, for selection (0 = all)` — выбор конкретного BMS на шине (0 = все) |

Выходные файлы: `/tmp/jkbms_last.json` (последний снимок, перезапись), `/tmp/jkbms_stats.json` (накопительный лог, дозапись).

### sbin/pv1800_ctrl.py

| Константа | Значение по умолчанию | Что регулирует |
|---|---|---|
| `SLAVE_ID` | `0x04` | Slave-адрес инвертора на шине Modbus |
| `DEVICE` | `/dev/ttyINV0` (стабильный udev-алиас, см. выше) | Serial-устройство для связи с инвертором |
| `BAUDRATE` | `19200` | Скорость порта |
| `CMD_FILE` | `/root/inverter_cmd.lst` | Файл команд на запись в регистры инвертора (формат `адрес=>значение`, используется и `batmon.php` для переключения режима) |
| `ADDR` | `20000` | Базовый адрес блока регистров для опроса |
| `PV1800_ID` | `20566` | Адрес регистра/идентификатор модели инвертора |

Выходные файлы: `/tmp/inverter_last.json`, `/tmp/inverter_accum.json`, `/tmp/inverter_cfg.json`, `/tmp/inverter_raw.json` (все — перезапись), `/tmp/inverter_stats.json` (дозапись, только при значимом изменении токов).

### mqtt/mqtt-client.php

| Константа/переменная | Значение по умолчанию | Что регулирует |
|---|---|---|
| `$server` | `rpi3-ha.local` | Хост MQTT-брокера |
| `$port` | `1883` | Порт MQTT-брокера |
| `$clientId` | `SolarStation` | MQTT client id |
| `OUTDATED_TRESH` | `1` | Порог (в единицах, используемых при построении discovery/публикации), после которого данные считаются устаревшими |
| `SENSOR_PATH` | `homeassistant/sensor/solar_station` | Префикс топиков Home Assistant MQTT discovery для сенсоров |
| `SWITCH_PATH` | `homeassistant/switch/solar_station` | Префикс топиков Home Assistant MQTT discovery для переключателей |

Запуск: `php mqtt-client.php /etc/MQTT_creds`. Скрипт проверяет `argc > 1` — если аргумент (путь к файлу с credentials) передан, читает его; иначе использует заглушку `$creds = 'user password'` из кода.

## Пороги batmon.php

Простые пороги (без гистерезиса):

| Порог | Значение | Что запускает |
|---|---|---|
| `$v_min < 2.7` | 2.7 В | Отправка `ALERT`-события "Low voltage on cell" |
| `$v_min > 3.6` | 3.6 В | Отправка `ALERT`-события "High voltage on cell" |
| `$elps > 10` (минут) | 10 минут | Данные BMS считаются устаревшими: `ALERT`-событие "BMS stats outdated for N minutes" и аварийное завершение скрипта |
| `abs($obj->battery_current) > 50` | 50 А | `ALERT`-событие "Abnormal high current on {device_id}" |

**Переключение on-grid/off-grid — с гистерезисом.** В отличие от простых порогов выше, решение о переключении инвертора принимается не по одному замеру, а по счётчику `$on_grid` (от `-5` до `+5`, хранится между запусками в `/tmp/on_grid.cntr`), который сдвигается на ±1 при каждом запуске `batmon.php` (каждые 5 минут по cron) в сторону "нужно включить сеть" или "нужно выключить сеть", и восстанавливается к нулю при обратных показаниях. Реальное переключение происходит только в момент, когда счётчик впервые достигает крайнего значения (`5` или `-5`) — то есть после 5 подряд "согласных" замеров (порядка 25 минут), что защищает от дребезга на разовых просадках/пиках.

| Условие сдвига счётчика | Значение | Что происходит при достижении края |
|---|---|---|
| `ongrid_switch == 0 && $v_min <= 3.21` | 3.21 В на ячейку | Счётчик растёт к `+5`. По достижении `5`: запись `20105=>1` в `/root/inverter_cmd.lst` (включение On-Grid) + `WARN`-событие с деталями (`v_min`, `SoC`, суммарная зарядная/инверторная мощность, накопленная энергия) |
| `ongrid_switch == 1 && (($v_min >= $offgrid_start && $chg_pow >= $pow_min) \|\| $v_min >= 3.5)` | `$offgrid_start` (по умолчанию **3.32 В**, переопределяется первым CLI-аргументом `batmon.php`) при достаточной суммарной зарядной мощности, либо безусловно при `≥ 3.5 В` | Счётчик снижается к `-5`. По достижении `-5`: запись `20105=>0` в `/root/inverter_cmd.lst` (выключение, переход на автономное питание от солнца/батареи) + `WARN`-событие |

Где:
- `$chg_pow` — суммарная зарядная мощность (`battery_voltage × $total_current`), а `$total_current` складывается из тока заряда встроенного контроллера PV1800 (`inverter_last.json → PV_charger->chg_curr`) и тока внешнего MPPT-контроллера Epever (`/tmp/epever_dump.json → battery_current`, если файл есть и валиден — иначе эта составляющая считается нулём и пишется предупреждение в лог);
- `$pow_min` — минимальная зарядная мощность для допуска к отключению сети, `max(640 Вт, 97% текущей мощности нагрузки)` — то есть порог подстраивается под текущее потребление, а не фиксирован;
- `$offgrid_start` — единственный параметр, настраиваемый без правки кода: `php batmon.php 3.30` временно/постоянно (в зависимости от того, как вызывается из cron) меняет напряжение-порог начала отсчёта на отключение сети.

Также ежедневно в промежутке `15:00–21:59` в начале каждого часа (`$M == 0 && $H >= 15 && $H <= 21`) отправляется `REPORT`-событие со статусом (диапазон часов изменён относительно более ранней версии скрипта — было `18:00–22:59`).

## Файлы секретов

| Файл | Формат содержимого | Кто использует |
|---|---|---|
| `/etc/MQTT_creds` | Одна строка вида `user password` (логин и пароль через пробел, разбирается `explode(' ', $creds)`) | `mqtt/mqtt-client.php`, передаётся как аргумент CLI |
| `/etc/telebot` | Одна строка — URL сервиса telebot (например `http://host:port`), используется как база для `GET {telebot_srv}/reg_event.php?...` | `sbin/batmon.php` (функция `send_event`) |

Права доступа на оба файла стоит ограничить: `chmod 600`, владелец — тот пользователь, от имени которого запускаются скрипты (cron/systemd).

## Известные hardcoded-предположения, которые нужно проверить при разворачивании на новом окружении

- `sbin/pool_devices.sh` содержит `cd /home/alpet/solar` — абсолютный путь к домашней директории конкретного пользователя (`alpet`) и его venv (`./venv/bin/activate`). При разворачивании на другом окружении/пользователе этот путь нужно поменять.
- `sbin/pool_devices.sh` также содержит `cp -f ~/root/inverter*.log /var/www/html` — смешение `~` и абсолютного `/root`, стоит перепроверить при переносе.
- ~~Устройства `/dev/ttyUSB0` (JKBMS) и `/dev/ttyACM0` (инвертор) — конкретные имена, присвоенные ядром конкретным USB-адаптерам~~ — **уже закрыто**: скрипты используют стабильные udev-алиасы `/dev/ttyBMS0`/`/dev/ttyINV0`, см. [Стабильные имена устройств (udev)](#стабильные-имена-устройств-udev) выше. На новом хосте всё равно нужно один раз проверить `idVendor`/`idProduct`/`serial` под конкретные физические адаптеры — правило из этого репозитория привязано к серийникам конкретных устройств референсной инсталляции.
- Hostname MQTT-брокера `rpi3-ha.local` в `mqtt/mqtt-client.php` — специфичен для референсной инсталляции Home Assistant.
- Пути `/root/inverter_cmd.lst`, `/backup/jkbms`, `/backup/inverter` подразумевают, что скрипты выполняются с правами `root` и что каталоги `/backup/jkbms` и `/backup/inverter` заранее созданы.
