# Установка и развёртывание

## Требования

Кратко (подробности об архитектуре и назначении компонентов — в [обзоре](01-overview.md)):

- Инвертор **MUST PV1800-5048VHM** и BMS **JKBMS PB2A17S-20P**, подключённые по RS485.
- Миникомпьютер рядом с инвертором с двумя USB-RS485 адаптерами (в референсной инсталляции — ASUS TinkerBoard 1.2 на Armbian). На нём крутятся Python-дамперы (`jkbms_ctrl.py`, `pv1800_ctrl.py`) и PHP-скрипты (`batmon.php`, `mqtt-client.php`, веб-мониторинг).
- Отдельный миникомпьютер или VM с Home Assistant + MQTT + InfluxDB + Grafana (рекомендуется Raspberry Pi с 64-битной ОС) — принимает данные по MQTT.
- Солнечные панели и батарея LiFePO4 на 48В.
- Linux-система с apt и python3-pip (инструкции ниже проверены на Armbian/Debian-подобных системах).

## Установка пакетов

Системные пакеты:

```sh
apt -y install apache2 php php-curl libapache2-mod-php python3 python3-pip
```

Python-модули устанавливаются внутри venv:

```sh
python3 -m venv venv
source ./venv/bin/activate
pip3 install pyserial minimalmodbus pymodbus
```

Скрипты `pv1800_ctrl.py` и `jkbms_ctrl.py` должны запускаться из активированного venv (см. пример в `sbin/pool_devices.sh`, где перед запуском выполняется `source ./venv/bin/activate`).

## Размещение файлов

Файлы репозитория раскладываются по системе следующим образом:

| Из репозитория | Куда | Назначение |
|---|---|---|
| `mqtt/` | `/root` | `mqtt-client.php` и связанные с ним файлы состояния/лог-файлы |
| `sbin/` | `/usr/local/sbin/` или `/usr/sbin/` | Дамперы `jkbms_ctrl.py`, `pv1800_ctrl.py`, монитор `batmon.php`, а также `backup_stats.sh`, `pool_devices.sh`, `jkbms_enable_chg.sh` |
| `html/` | `/var/www/html` | Веб-страница мониторинга (`index.php`) |

Кроме того, PHP-скрипты (`batmon.php`, `mqtt-client.php`) подключают `lib/common.php` и `lib/esctext.php`, которых нет в этом репозитории — они поставляются отдельным репозиторием **alpet-libs**. Его нужно установить в `/usr/share/php/lib`, иначе `require_once` в этих скриптах завершится ошибкой.

## Файлы секретов и конфигурации

Для работы скриптам требуется несколько файлов вне репозитория:

- `/etc/MQTT_creds` — учётные данные MQTT-брокера в виде одной строки `user password`. Читается `mqtt-client.php`, который запускается с этим файлом в качестве аргумента: `php mqtt-client.php /etc/MQTT_creds`.
- `/etc/telebot` — адрес сервиса Telegram-бота, используемого `batmon.php` для отправки алертов.

Это минимальный набор, необходимый для установки. Подробный разбор всех конфигурационных файлов и параметров — в отдельном документе [Конфигурация](03-configuration.md).

## Веб-мониторинг (опционально)

Если планируется использовать веб-страницу мониторинга (`html/index.php`), нужно внести правку в юнит apache2, разрешив ему видеть общий `/tmp`:

```
# /etc/systemd/system/multi-user.target.wants/apache2.service
PrivateTmp=false
```

Причина: Python-дамперы и PHP-скрипты обмениваются данными через файлы в `/tmp` (`jkbms_last.json`, `inverter_last.json`, `inverter_accum.json`, `inverter_cfg.json` и т. д.). По умолчанию systemd включает `PrivateTmp=true` для apache2, из-за чего сервис получает изолированный `/tmp` и не видит эти файлы. Отключение `PrivateTmp` — сознательное ослабление изоляции сервиса ради простоты обмена данными; если веб-мониторинг не используется, эту правку вносить не нужно.

После правки перезагрузите конфигурацию systemd и перезапустите apache2:

```sh
systemctl daemon-reload
systemctl restart apache2
```

## Планировщик задач (cron/systemd)

Согласно исходной инструкции, расписание настраивается через `crontab -e`:

- `backup_stats.sh` — раз в сутки;
- дамперы (`jkbms_ctrl.py`, `pv1800_ctrl.py`) и `batmon.php` — с интервалом 1–5 минут;
- `mqtt-client.php` — с интервалом от 1 часа и чаще, с параметром — путём к файлу с учётными данными: `php mqtt-client.php /etc/MQTT_creds`.

> **Примечание.** По итогам код-ревью (см. [обзор безопасности и планы](08-security-roadmap.md)) для долгосрочной эксплуатации рекомендуется переход с cron+nohup на systemd-юниты с `Restart=always`. Это сокращает окно недоступности при падении процесса (cron заново запустит задачу только на следующем тике расписания, а не сразу) и делает применение команд из `/root/inverter_cmd.lst` в связке с Home Assistant более предсказуемым по времени — команды переключения инвертора не должны ждать до 5 минут следующего запуска cron. Здесь не приводится готовый unit-файл — это направление для отдельной проработки; ориентировочно речь идёт о `Type=simple` (или `Type=oneshot` с `Restart=always` для периодических дамперов) сервисах, запускающих скрипты из venv напрямую, без обёрток через nohup.

## Проверка после установки

После установки и настройки расписания стоит убедиться, что система действительно работает:

1. **Свежесть данных дамперов.** Проверьте, что файлы `/tmp/jkbms_last.json` и `/tmp/inverter_last.json` существуют и обновляются с ожидаемым интервалом:
   ```sh
   ls -la /tmp/jkbms_last.json /tmp/inverter_last.json
   ```
   Время модификации не должно отставать от текущего больше, чем на интервал запуска дамперов (1–5 минут).

2. **Отсутствие ошибок в логах.** Дамперы и `pool_devices.sh` пишут stdout/stderr в `/tmp/*.log` и `/tmp/*.err` (например, `/tmp/jkbms_ctrl.log`, `/tmp/jkbms_ctrl.err`, `/tmp/pv1800_ctrl.log`, `/tmp/pv1800_ctrl.err`, `/tmp/mqtt-client.log`). Файлы `*.err` в норме должны быть пустыми либо не содержать свежих ошибок:
   ```sh
   tail -n 50 /tmp/*.err /tmp/*.log
   ```

3. **Публикация в MQTT/Home Assistant.** Убедитесь, что `mqtt-client.php` успешно подключается к брокеру и публикует данные — проще всего проверить появление соответствующих сущностей/значений в Home Assistant либо подписаться на топик напрямую через `mosquitto_sub` на сервере MQTT.

Если что-то из перечисленного не выполняется, стоит свериться с размещением файлов (раздел выше) и наличием библиотек `alpet-libs` в `/usr/share/php/lib`, а также с корректностью прав доступа к `/dev/ttyUSB0` и `/dev/ttyACM0` (используются `jkbms_ctrl.py` и `pv1800_ctrl.py` соответственно) — подробнее о рисках, связанных с правами доступа к `/root/inverter_cmd.lst` и портам устройств, см. [обзор безопасности и планы](08-security-roadmap.md).
