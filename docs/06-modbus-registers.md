# Справочник регистров/параметров Modbus и JK RS485

## 1. Обзор

Это справочник структур регистров и параметров, которые используются в коде двух управляющих скриптов — `sbin/jkbms_ctrl.py` (протокол JK RS485 v2.5, BMS) и `sbin/pv1800_ctrl.py` (Modbus RTU, инвертор/зарядный контроллер PV1800). Документ не описывает сами скрипты (см. [04-scripts-reference.md](04-scripts-reference.md)) — он собирает в одном месте все таблицы кодов/адресов/коэффициентов, разбросанные по коду, и сверяет их с официальной документацией там, где она доступна.

Для инвертора семейства PV1800/PH1800/EP1800/PV3500/EP3500 в корне репозитория лежит файл `protocol.xlsx` — это официальный протокол Modbus RTU производителя, первоисточник для всех адресов регистров инвертора и зарядного контроллера. Все таблицы по инвертору в разделах 3–8 ниже сверены с этим файлом (листы `Inverter modbusRTU (ID == 4)` и `PV Charger ModbusRtu (ID == 4)`); где сверка выполнена явно, это отмечено.

Для JKBMS аналогичного официального документа в репозитории **нет**. Коды параметров и коэффициенты в таблице `bms_params` получены практически — из наблюдения за реальным трафиком BMS и сторонних реализаций протокола JK RS485 v2.5 (публичные проекты, реверс-инжиниринг). Это означает, что часть имён и коэффициентов в разделе 2 не подтверждена официальной спецификацией и должна восприниматься как рабочая, но не гарантированно точная информация.

> **NOTE из предыдущего фикс-спринта.** В `bms_params` ранее присутствовала дублирующая запись `[0xad, 1, "current_calibr", 1]`, которая конфликтовала по коду `0xad` с `prot_board_addr` (сканирование списка в `decode_response` останавливается на первом совпадении, поэтому вторая запись была недостижима и никогда не декодировалась). Эта запись была удалена как мёртвый код. Если реальный код регистра калибровки тока (`current_calibr`) станет известен — его можно добавить обратно с правильным (не конфликтующим) кодом. Комментарий с этим объяснением сохранён прямо в `sbin/jkbms_ctrl.py` рядом с `bms_params` (после элемента `0xad`).

### Фиксированные поля телеметрии (0x79, 0x80–0x8c, 0xb2 и далее)

Эти коды не входят в `bms_params` — они разбираются отдельными ветками `if/elif` прямо в `decode_response` (не через таблицу с коэффициентом), потому что имеют нестандартный формат (переменная длина, знаковые значения, строки).

| Код (hex) | Ключ в результирующем пакете | Формат / декодер | Значение |
|---|---|---|---|
| `0x79` | `cells` | `decode_cells` — блок переменной длины, по 3 байта на ячейку (1 байт номер + 2 байта мВ) | Напряжения отдельных ячеек батареи, словарь `{номер: вольты}` |
| `0x80` | `MOS_temp` | `decode_temp` (2 байта, значения >100 трактуются как отрицательные — "холодная сторона") | Температура MOSFET-ключей, °C |
| `0x81` | `battery1_temp` | `decode_temp` | Температура датчика батареи №1, °C |
| `0x82` | `battery2_temp` | `decode_temp` | Температура датчика батареи №2, °C |
| `0x83` | `battery_voltage` | `decode_num16`, коэфф. 0.01 | Напряжение батареи, В |
| `0x84` | `battery_current` | `decode_current` (2 байта, старший бит — знак, коэфф. 0.01) | Ток батареи, А (со знаком: заряд/разряд) |
| `0x85` | `battery_SoC` | `decode_num8` | Уровень заряда батареи, % |
| `0x86` | `temps_sensors` | `decode_num8` | Количество подключённых датчиков температуры |
| `0x87` | `cycle_count` | `decode_num16` | Число циклов заряд/разряд |
| `0x89` | `cycle_capacity` | `decode_num32` | Накопленная ёмкость по циклам (Ач) |
| `0x8a` | `total_battery_str` | `decode_num16` | Число ячеек батареи (фактически определённое) |
| `0x8b` | `battery_warn_msg` | `decode_num16` | Битовая маска предупреждений BMS |
| `0x8c` | `battery_status_info` | `decode_num16` | Битовая маска статуса BMS |
| `0xb2` | *(не сохраняется в пакет)* | `decode_str`, 10 байт, UTF-8 | Пароль BMS (`bms_pwd`) — читается, но не кладётся в итоговый `packet` |
| `0xb4` | `device_id` | `decode_str`, 8 байт, UTF-8 | Идентификатор устройства BMS |
| `0xb5` | `date_manufact` | `decode_str`, 4 байта, UTF-8 | Дата производства |
| `0xb7` | `firmware_ver` | `decode_str`, 15 байт, UTF-8 | Версия прошивки BMS |
| `0xba` | `id_manufact` | `decode_str`, 24 байта, UTF-8 | Идентификатор производителя/партии |

Код `0x00` завершает разбор кадра (`packet['complete'] = 1`); любой не распознанный код (не найден ни в `bms_params`, ни в списке фиксированных полей выше) прерывает разбор с предупреждением `#WARN: breaking decode with tail ...`.

## 3. Инвертор PV1800 — базовые адреса блоков

Скрипт `sbin/pv1800_ctrl.py` читает регистры инвертора и зарядного контроллера через `read_regs(addr, count)` (Modbus RTU, holding registers). Ниже — базовые (стартовые) адреса блоков, которые используются как `addr` при чтении, и списки-описатели (`descr`), через которые `map_values()` разбирает прочитанный массив регистров по смещениям (`offset` в `descr`, а не абсолютный адрес).

| Список в коде | Базовый регистр | Что читает |
|---|---|---|
| `charger_info` | `15201` | Информационные (RO) регистры зарядного контроллера — состояние, PV/батарея, температуры, реле, ошибки |
| `IGL` (в блоке 25201) + сопутствующие смещения | `25201` | Большой блок телеметрии инвертора в реальном времени: состояние, напряжения, токи, мощности, частоты, температуры, реле, накопленные счётчики, серийный номер, версии ПО, батарея |
| `calibration_params` | `20000` (`ADDR`) | Коэффициенты калибровки измерительных цепей инвертора (напряжения/токи), смещения 9–15 от `ADDR` |
| `config_params` | `20101` | Конфигурационные (RW) параметры инвертора — режимы работы, пороги, приоритеты источника |
| `charger_params` | `10001` | Идентификация и калибровочные коэффициенты зарядного контроллера |
| `batt_params` | `10101` | Параметры заряда батареи (напряжения, токи, тип, ёмкость, выравнивание) |
| — (машинный ID) | `20000` (`ADDR`) | Однорегистровое чтение в `using_pymodbus`/`using_mini` для проверки типа устройства (`midx == PV1800_ID`), а также первые 16 регистров с `ADDR` читаются в `read_loop` для машинного ID, серийного номера, версий и калибровки |

Все базовые адреса подтверждены по `protocol.xlsx` (листы `Inverter modbusRTU (ID == 4)` и `PV Charger ModbusRtu (ID == 4)`): `15201` — начало блока "PV Charger Display Message", `25201` — начало блока "Inverter Display Message", `20101` — начало "Inverter Control Message" (RW-часть), `20000` — "The type of machine High/Low" в начале "Inverter Control Message", `10001` — начало "PV Charger Control Message", `10101`+2=`10103` — первый реально используемый регистр конфигурации заряда (`10101`/`10102` в файле не описаны явно, реестр начинается практически с `10103`).

## 4. Инвертор PV1800 — параметры зарядного контроллера (`charger_info`, база 15201)

Список `charger_info` в `sbin/pv1800_ctrl.py`, читается блоком `read_regs(15201, 22)`. Формат элемента `descr`: `"offset:имя[:тип]"`, где тип `i` — знаковое 16-битное число, число (например `1`) — количество знаков после запятой (значение делится на `10^N`).

| Смещение | Абс. регистр | Имя в коде | Тип | Значение (по `protocol.xlsx`) |
|---|---|---|---|---|
| 0 | 15201 | `workstate` | int | Состояние контроллера: 0 Init, 1 Selftest, 2 Work, 3 Stop |
| 1 | 15202 | `MPPT_state` | int | Режим MPPT: 0 Stop, 1 MPPT, 2 Current limiting |
| 2 | 15203 | `charging_state` | int | Стадия заряда: 0 Stop, 1 Absorb, 2 Float, 3 EQ |
| 4 | 15205 | `PV_volt` | ×0.1 | Напряжение PV-панелей, В |
| 5 | 15206 | `batt_volt` | ×0.1 | Напряжение батареи, В |
| 6 | 15207 | `chg_curr` | ×0.1 | Ток заряда, А |
| 7 | 15208 | `chg_power` | int | Мощность заряда, Вт |
| 8 | 15209 | `rad_temp` | int | Температура радиатора, °C |
| 9 | 15210 | `ext_temp` | int | Внешняя температура, °C |
| 10 | 15211 | `batt_relay` | int | Состояние реле батареи (0/1) |
| 11 | 15212 | `PV_relay` | int | Состояние реле PV (0/1) |
| 12 | 15213 | `err_msg` | int | Код(ы) ошибок контроллера |
| 13 | 15214 | `warn_msg` | int | Код(ы) предупреждений контроллера |
| 14 | 15215 | `batt_volt_grade` | int | Номинальное напряжение батареи (класс), В |
| 15 | 15216 | `rated_curr` | ×0.1 | Номинальный ток контроллера, А |

Регистр 3 (offset 3, абс. 15204) — зарезервирован, пропущен и в коде, и в протоколе.

## 5. Инвертор PV1800 — реального времени/IGL (`IGL`, база 25201)

Базовый список `IGL = ['0:inverter:i', '1:grid:i', '2:load']` переиспользуется в `scan_realtime()` с разными смещениями относительно блока, прочитанного `read_regs(25201, 79)` — то есть значения `IGL` разбираются один и тот же трёхэлементный шаблон "инвертор/сеть/нагрузка" (I/G/L), но по разным группам регистров:

| Использование в коде | Смещение | Абс. регистры | Значение |
|---|---|---|---|
| `data['power'] = map_values(registers, IGL, 12)` | `+12` | 25213–25215 | Активная мощность P: инвертор/сеть/нагрузка (Вт); далее пересчитывается через `calc_p` при необходимости |
| `data['S'] = map_values(registers, IGL, 16)` | `+16` | 25217–25219 | Полная мощность S: инвертор/сеть/нагрузка (ВА) |
| `data['Q'] = map_values(registers, IGL, 20)` | `+20` | 25221–25223 | Реактивная мощность Q: инвертор/сеть/нагрузка (вар) |
| `relays = map_values(registers, IGL, 36)` | `+36` | 25237–25239 | Состояние реле: инверторное/сетевое/нагрузки (0/1) |

Кроме собственно `IGL`, из того же блока `25201` разбираются и другие поля (списки `descr` заданы инлайн в `scan_realtime`):

| Смещение | Абс. регистры | Ключ в `data` | Значение |
|---|---|---|---|
| 0 | 25201 | `inv_workstate` | Состояние инвертора (0 PowerOn … 6 Grid charging) |
| 1 | 25202 | `AC_volt_grade` | Класс переменного напряжения (230/120) |
| 2 | 25203 | `rate_power` | Номинальная мощность, ВА |
| 15 | 25216 | `load_percent` | Загрузка инвертора, % |
| 4–7 | 25205–25208 | `voltages` (`battery/inverter/grid/bus`) | Напряжения ×0.1, В |
| 8–11 | 25209–25212 | `current` (`control/inverter/grid/load`) | Токи ×0.1, А |
| 24–25 | 25225–25226 | `inv_freq`, `grid_freq` | Частоты ×0.01, Гц |
| 32–34 | 25233–25235 | `temp_sensors` (`AC_radiator/transformer/DC_radiator`) | Температуры, °C |
| 39–41 | 25240–25242 | `relays` доп. поля (`neutral/DC/earth`) | Состояние реле, 0/1 |
| 44–59 (шаг 2) | 25245–25260 | накопленные счётчики (`accu`, отдельный файл) | Пары регистров "мегаватт-часы (`*1000`) + 0.1 кВт·ч" для 8 счётчиков: `charger_power, discharger_power, buy_power, sell_power, load_power, self_use, PV_sell_power, grid_charger` |
| 60,61,62,64,65 | 25261,25262,25263,25265,25266 | `messages` (`err_1/err_2/err_3/warn_1/warn_2`) | Коды ошибок/предупреждений инвертора |
| 68–69 | 25269–25270 | `serial` | Серийный номер (два регистра, hi/lo → hex-строка) |
| 70–78 (частично) | 25271… | `hw_ver, sw_ver, rated_power(+6=25277), comm_proto_ver(+7=25278), arrow_flags(+8=25279)` | Версии ПО/железа, номинальная мощность (Вт), версия протокола, битовые флаги стрелок на дисплее |
| 72–74 | 25273–25275 | `battery` (`power:2, curr:i, volt_grade`) | Мощность батареи (×0.01), ток батареи (знаковый), класс напряжения батареи |

Смещение накопленных счётчиков (44) в коде подтверждено собственным комментарием: `ofs = 44  #  25245 - 25201`, что совпадает с `protocol.xlsx` (`Accumulated charger power high` = 25245).

## 6. Инвертор PV1800 — калибровка (`calibration_params`)

`calibration_params` используется в `read_loop()` через `data['calibration'] = map_values(registers, calibration_params)`, где `registers` — результат `read_regs(ADDR, 16)`, `ADDR = 20000`. Смещения в `calibration_params` (9–15) отсчитываются от того же `ADDR = 20000` (вызов `map_values` без явного `offset`, но сам массив `registers` уже начинается с `ADDR`), то есть базовый адрес блока калибровки — **20000**, а не отдельная константа.

| Смещение (от 20000) | Абс. регистр | Имя в коде | Значение |
|---|---|---|---|

## 9. Как этим пользоваться

- **`/root/inverter_cmd.lst`** — файл команд записи для `pv1800_ctrl.py` (`process_cmd()`/`parse_cmds()`). Формат строки — `<адрес>=><значение>`, где `<адрес>` — это **абсолютный номер регистра** (например `20128` для `batt_high_volt`), а не смещение из таблиц выше. Чтобы записать параметр из раздела 7 или 8, нужно сложить базу и смещение из соответствующей таблицы (например `batt_high_volt` из `config_params`: база 20101 + смещение 27 = `20128=><значение>`). Разрешены только диапазоны `10101–10124` и `20002–20144` (проверка в `process_cmd`); попытка записи за их пределами отклоняется с `#ERROR: outrange address value`.
- **CLI `jkbms_ctrl.py`** — флаг `--id` принимает **код параметра напрямую** (значения из раздела 2, например `0xb1` для `low_volume_alarm`), а не смещение или индекс в списке — код параметра в протоколе JK RS485 v2.5 и есть первый байт полезной нагрузки кадра чтения/записи (см. `format_rqs`), никакого пересчёта через базовый адрес, в отличие от Modbus-регистров инвертора, не требуется.
